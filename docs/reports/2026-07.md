## Shipped

- [EP-33](../stories/ep-33-port-monitoring.md) Port (TCP) monitoring — Jul 1, full epic (5/5). Fifth monitor type: raw TCP connect checks for non-HTTP services (mail servers, databases, custom daemons), same up/down/incident/alert model as the uptime monitor. Migration 025 added `port_monitors`/`port_checks`/`port_incidents` and a `port_expected_state` enum. The standout feature is the **expected state** toggle: "open" (default) alerts if the port stops accepting connections, "closed" inverts that into a security check — alerting if a port that should be firewalled off unexpectedly becomes reachable. Wired into the aggregate monitor limit (ADR-019, revised), maintenance windows, and status pages alongside the other four types. Two scope simplifications versus the original story, both noted in the epic file: a DNS-resolution failure isn't distinguished from connection-refused/timeout (both just mean "couldn't connect" — the `monitor_status` enum this reuses has no `error` state to put it in, and reliably telling them apart needs an extra lookup call), and the "2 consecutive failures" flap-avoidance wording (copied from EP-03's original spec) was corrected to reflect that both monitor types actually use the `alert_after_n_failures` filter added later.
